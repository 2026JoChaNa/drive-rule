# 012 — 보호구역 접근·목적지 이벤트와 차량 내부 위치 대조

날짜: 2026-11-15 · 상태: 구현, 기기 검증 전

## 범위

Figma의 B(목적지 주변 보호구역 주정차)·H(보호구역 진입)를 011의 I(우회전) 공통 안내 경로에 추가한다. A(고속도로 주정차)는 현재 도로 종류를 확정할 입력이 없어 보류한다. `P`, 주차 브레이크, IC 안내 또는 고속도로 경로 옵션만으로 현재 도로를 추정하지 않는다. [원본과 검증 기록](../spatial-events-2026-11-15.md)을 함께 읽는다.

## 입력과 보관

- Pleos FusedLocation 1.1.3의 연속 콜백을 사용한다. 현재 차량 좌표는 메모리에서만 사용하며 기록·전송하지 않는다. confidence는 정확도 반경으로 해석하지 않는다.
- 위치 timestampMillis의 clock 기준은 문서에 없다. 최초 유효 timestamp는 baseline으로 소비하고 엄격히 증가하는 다음 timestamp부터 수신 시각 기준 Fresh로 처리한다. 수신이 5초 끊기면 만료하며 연속성 세대를 바꾼다. 재개 첫 위치 역시 진입으로 처리하지 않는다. 절대 측정 시각이나 위치 정확도를 검증했다는 뜻은 아니다.
- NaviHelper 3.0.5에서 목적지 위도·경도·remainDistance만 메모리에 유지한다. 이름·주소·POI·경로 이력은 저장하지 않는다. 경로 상태와 목적지는 5초마다 조회하며 응답 없는 조회는 freshness를 갱신하지 않는다. 10초가 지나면 보류한다.
- 학교 시설 좌표는 기존 schema 1 API의 manifest/ETag/상대 파일 URL을 사용한다. gzip 해제 후 크기·SHA-256·스키마·기준일·건수·유한 좌표를 검증한 완전 사본만 noBackup AtomicFile로 교체한다. 기존 Room/서버 ERD는 변경하지 않는다. 차량·목적지 좌표는 downloader 인자로도 전달하지 않는다.
- 법령 동기화와 별개 WorkManager 작업으로 앱 진입 및 하루 간격에 갱신한다. 최초 사본이 없으면 B/H만 보류한다. 실패하면 마지막 검증 사본을 유지하며 날짜 표시는 갱신 여부 판단에 사용하지 않는다. 모든 시설을 SDK 근접 알림 슬롯에 등록하지 않고 연속 위치를 차량 안에서 대조한다.

## 개발 판정값

| 이벤트 | 진입 | 재무장·추가 조건 |
| --- | --- | --- |
| H `SCHOOL_ZONE_ENTRY` | 현재 위치가 가장 가까운 시설에서 370m 이내 | 먼저 모든 시설에서 470m 이상 떨어진 Fresh 관측 필요. 활성 내비 경로는 불필요 |
| B `PARKING_DESTINATION` | 목적지가 시설에서 300m 이내이고 경로 남은 거리 500m 이하 | 같은 목적지·경로에서 먼저 남은 거리 600m 이상 관측, Fresh 활성 경로 필요 |
| I `RIGHT_TURN_CROSSWALK` | 첫 TBT가 정확한 TURN_RIGHT이며 150m 이하 | 011의 200m 재무장 정책 유지 |

모두 연결된 실제 전진 기어·Fresh 속도와 알려진 실제 CarUxRestrictions를 요구한다. P나 속도 0으로 조작 허용을 추정하지 않는다. B/H의 첫 관측이 이미 안쪽이면 진입을 만들지 않으며, 지도 교체·목적지 교체·경로/위치 연속성 변경도 다시 초기화한다. 인접 시설의 반경이 겹친 동안은 연속 접근으로 다뤄 재안내를 늘리지 않는다.

시설 좌표와 구형 거리의 근사는 **법적 보호구역 경계·진입 도로·현재 위반 여부**를 판정하지 않는다. H에는 도로상 남은 거리나 ETA를 만들지 않는다. B에는 내비의 남은 거리만 사용한다. 370/470/300/500/600m는 개발값이며 차량 검증 후 조정한다.

## 출력과 취소

- 같은 순간의 우선순위는 I → H → B다. 그 안에서 011의 검수 카드 우선순위를 적용한다. 하나를 선택하며 대기열·실패 후 다른 카드 재생은 없다.
- 학교 지도 해시, 해당 시설, 목적지, 위치 연속성 세대를 후보 근거로 보관하고 실행 직전에 다시 확인한다. 바뀐 근거·오래된 신호·회수·프로필 변경은 대기 및 발화를 취소한다. 카드 원문 ttsText를 임의 요약하지 않는다.
- 011의 최대30초 후보, 원문 발화 적합성, 최대8초 시각 안내와 영속 예약을 공유한다. **운전자별 최근24시간 최대2회 시도, 60초 간격**도 그대로다. 따라서 같은 운전자로 세 이벤트를 연속 만들었다고 세 번 모두 출력되는 설정은 아니다. 실패·취소도 예약을 소비한다. 이 수치는 실차 검증 전 개발 정책이다.
- Figma 설명의 말풍선은 음성 시연 주석이다. 기존 사용자 요청에 따른 전면 배너·백그라운드 EVENT 알림을 유지하며, Figma의 말풍선을 차량 전체 화면 위 overlay로 구현하지 않는다.

## 위치 서비스 수명

`specialUse|location`을 선언하고 실제 위치를 시작하기 전에 location FGS 유형으로 승격한다. Pleos FUSED_LOCATION과 Android COARSE 또는 FINE 및 시스템 위치 켜짐을 모두 확인한다. 승격은 앱이 보일 때만 시도하고 권한 복귀는 RESUMED 시점에서 재확인한다. 백그라운드 타이머는 승격을 시도하지 않는다. 권한/시스템 위치 상실·서비스 종료 시 위치를 해제한다. ACCESS_BACKGROUND_LOCATION은 요청하지 않는다.

위치 접근 실패가 I의 내비 입력 경로를 막지 않는다. background Activity·overlay·임의 wake lock·boot 자동 재시작은 추가하지 않는다. SDK release가 내부 연결 재시도 coroutine을 취소하지 않는 한계는 종료된 Context lease에서 새 bind와 late connection을 차단해 다룬다. SDK 내부 작업 자체는 잠시 남을 수 있다.
