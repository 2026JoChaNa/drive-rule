# 008. Android 화면과 주행 안내의 책임·수명 분리

- 날짜: 2026-11-12
- 상태: 결정 (Android 구조). 실제 Pleos 실행 host/표시 surface와 제품 정책 수치는 검증 대기.
- 근거: 사용자의 MVVM 대안 검토 후 프로젝트에 맞춘 구조 설계 요청.
- 상세: [Android 구조](../architecture.md), [개발 컨벤션](../../../android/CODEX_CONVENTIONS.md).

이 문서는 Android 전용 결정이다. 작업 범위를 정리하면서 공유 `docs/decisions/`에서 `docs/android/decisions/`로 옮겼으며 기존 참조 번호 008은 유지한다. 공유 결정 001~007의 위치나 상태를 바꾸지 않는다.

## 배경

이름 입력과 출발 전 목록은 화면 상태 중심이지만, 주행 안내는 신호·음성·카드·취소·타이머가 화면 밖에서도 이어질 수 있다. 모두 ViewModel에 두면 화면 수명과 안내 실행이 결합되고 재구독 때 재생이 중복될 수 있다.

## 결정

1. 화면은 Compose + ViewModel + immutable UiState/StateFlow의 UDF를 유지한다. 모든 화면에 MVI reducer나 UseCase를 강제하지 않는다.
2. `domain/event`와 `domain/guidance`에는 플랫폼과 무관한 판정·정책·상태 전이를 둔다. 출력 계약과 저장소 계약은 인터페이스로 둔다.
3. `app/guidance`에 향후 coordinator를 두어 한 안내 세션의 상태 변경·타이머·출력 실행을 직렬로 조정한다. 활성 세션은 하나이며 UI scope와 분리한다.
4. Pleos/AAOS·음성·카드 표시의 실제 구현은 `core/platform`이 맡는다. coordinator는 인터페이스에 의존하고 AppContainer에서 조립한다.
5. 음성/카드 상태, 요청 수락/실제 시작, 안내 종료/사용자 확인을 구분한다. 안내 ID와 실행 세대로 늦은 callback을 식별하고 취소된 출력의 정리까지 수행한다.
6. 프로세스 복구 시 불확실한 진행 작업을 자동 재생하지 않는다. 최소 로컬 중복 기록을 설계하되 DB와 SDK 사이의 정확히 한 번 실행은 보장하지 않는다.
7. 단일 `:app`과 생성자 주입을 유지한다. 필요한 기능을 구현할 때 타입을 추가한다. 새 프레임워크·모듈·서버 API·DB 스키마를 이 결정으로 확정하지 않는다.

## 영향과 경계

현재 MVVM Kotlin 코드는 유지한다. 기존 폴더의 책임 설명을 보완하고 coordinator·표시 adapter의 확장 위치를 추가한다. 이번에 정의한 안내 엔진은 아직 실행 코드가 아니다.

001~005의 이름·개인정보·게시/회수·검수 문구 계약을 변경하지 않는다. 006·007은 여전히 초안이다. 주행당 횟수, trigger 거리, cooldown, 카드 표시 시간, trip 판정, 실행 host/권한은 구현·장치 검증 전에 별도 확정한다.

아키텍처 분리는 백그라운드 실행 권한이나 시스템 위 카드 표시를 보장하지 않는다. 플랫폼 확인 결과나 구현 규모가 달라지면 이 결정을 다시 검토한다.
