# A04 — 실제 우회전 안내와 로컬 시도 예약

> 후속 변경: 같은 날 B/H 위치·목적지 입력을 연결했다. 이 문서의 “우회전만/학교·목적지 미구현”은 작업4 당시 범위이며, 현재 상태는 [위치 확장 결정 A05](A05-school-and-destination-events.md)를 따른다.

날짜: 2026-11-15 · 상태: 개발 정책 채택, 실차 수치·배포 적합성 검증 전

## 이유와 범위

작업 4에서 실제 신호, 검수된 법령 캐시와 작업 2의 출력을 연결한다. 현재 입력으로 판정할 수 있는 `RIGHT_TURN_CROSSWALK`를 먼저 지원한다. 학교 좌표 캐시·차량 위치·목적지 입력은 아직 미구현이며 현재 고속도로 여부를 확인할 입력도 없다. 나머지 이벤트를 추정으로 생성하지 않는다. [계약·검증 기록](../history/event-guidance-2026-11-15.md)을 함께 읽는다.

## 감지와 선택

- 연결된 내비의 Fresh 경로 활성과 첫 TBT `TURN_RIGHT`, `0 < distance <= 150m`가 진입 조건이다. 200m 이상 또는 확인된 다른 기동에서 재무장한다. 명시적인 경로 무효화/재연결은 routeRevision을 바꾼다. 이 revision은 trip ID나 외부 식별자가 아니다.
- 연결된 차량의 전진 기어와 유한한 0 이상 속도가 필요하다. 내비 10초/연속 속도 5초 만료, 잘못된 시각·단위·미수신은 보류한다. 실제 UX Unknown은 출력을 막고 Restricted에서는 입력 없는 안내만 허용한다. 속도나 기어로 UX를 추정하지 않는다.
- 진입은 차단 중에도 소비한다. 캐시·프로필·권한·오디오가 나중에 준비돼도 지난 접근을 재생하지 않는다. 대기열은 없으며 한 번에 한 안내만 선택한다.
- 24시간 이내 성공 동기화 사본의 GENERAL·정확한 eventTag만 선택한다. LAW → OPERATION, 시행 중 → 시행 예정 → 시행일 미제공, verifiedAt 내림차순 → ID 오름차순으로 결정한다. 지원 카드 형식의 최상위 ttsText를 그대로 사용하며 decision JSON의 Gleo 답변 행을 이벤트 규칙으로 해석하지 않는다.
- 가장 높은 우선순위의 한 사본을 선택한 뒤 예약이 거절되면 그 접근은 종료한다. 중복 카드 대신 다른 카드를 연달아 시도하거나 여러 문장을 순서대로 재생하는 순환 추천은 하지 않는다.
- 제목과 발화/본문은 동일 카드 사본이다. 날짜 상태·OPERATION 출처와 ‘현장 표지판 우선’은 별도 표시 맥락이다. 시행일이 없으면 시행 중으로 단정하지 않는다.

## 시점과 실행

- 후보는 최대 30초와 예상 도착 1초 전 중 빠른 기한을 가진다. 속도 0이면 도착 시각을 만들지 않는다. 최소 선행 시간 3초, 원문 초당 6자 발화 추정과 1초 여유를 적용하여 문장을 끝내기 어렵다면 건너뛴다. 발화 속도는 측정된 SDK 보장이 아니라 조정할 개발값이다.
- 서비스가 250ms마다 현재 입력을 재검증한다. 데이터 수신 시각을 타이머로 갱신하지 않는다. 프로필·경로·UX Unknown·권한 상실·회수·동일 버전 문구 변경·시행 단계 변경·기한 만료 시 대기와 출력을 취소한다.
- 비동기 예약 후 DB 사본과 프로필을 다시 읽고 실행 세대 및 최신 신호를 확인한다. UI 수집은 출력 명령을 만들지 않는다. 이름 등록 시작과 서비스 중지는 동기적으로 안내를 취소한다.
- 기존 Pleos 온디바이스 TTS/포커스/취소 경계를 사용한다. 자동 재시도/포커스 복귀 후 재생은 없다. 표시는 최대 8초이며 음성과 독립이다. 전면 배너와 백그라운드 무음 EVENT 알림을 오갈 때 최초 표시 기한을 유지한다. 알림 거부는 음성을 막지 않는다.
- 배너가 전체 원문과 맥락을 담을 수 없으면 시각 출력을 생략한다. 법령 문구를 임의 요약하거나 말줄임하지 않는다. 시스템 알림 레이아웃·heads-up 노출은 OS 정책을 따르며 임의 overlay는 쓰지 않는다.

## 중복과 복구

SDK 출력과 DB 기록은 한 트랜잭션이 될 수 없다. 출력 전에 차량 내부의 최소 **시도 예약**을 영속화한다. 성공한 예약은 음성 실패·취소·프로세스 종료에도 되돌리지 않는다. 이 선택은 안내 누락을 허용하며 정확히 한 번 재생을 보장하지 않는다.

- 중복 키: profileId + cardId + 시행 단계. 버전만 바뀐 교정은 자동 재안내하지 않는다.
- 개발 임시 제한: 같은 키 24시간, 같은 프로필 60초 간격, 같은 프로필 최근 24시간 최대 2회 시도. 실제 trip 경계를 아직 정의하지 않았으므로 ‘주행당 2회’ 구현으로 표현하지 않는다. 이 보수적 대체 정책은 기기 검증 후 제품 기준에 맞춰 조정한다.
- 같은 부팅에서는 단조 시각으로 경과를 비교하고 부팅이 달라지면 wall clock을 사용한다. 역행·손상·저장 실패는 출력 차단으로 처리한다. BOOT_COUNT를 읽을 수 없으면 해당 서비스 세션의 임의 토큰으로 다른 부팅처럼 취급한다. 어떤 토큰도 외부로 보내지 않는다.
- 최대 128개 유효 기록을 보관하고 만료된 기록만 다음 예약 시 정리한다. 파일은 noBackupFilesDir에 원자적으로 교체한다. 기록에는 숫자 프로필/카드 ID, 시행 단계, 시각과 로컬 부팅 표식만 있다.
- 기존 Room 프로필/법령 DB 및 서버 ERD는 변경하지 않는다. 이 예약은 notice_log/card_confirmation/들은 안내 횟수가 아니며 홈 이력으로 표시하지 않는다.

## 검증과 남은 범위

순수 정책·예약·비동기 취소·출력 전환을 JVM으로 검증하고 Debug/Release 및 UI 계측 APK를 빌드한다. 사용자의 테스트 일정에 따라 이번에는 기기 설치·실행·초기화·권한 조작을 하지 않는다. 실제 음성 선행 시점, 지도와 오디오 공존, 화면 물리 크기와 배포 허용은 [기기 검증 목록](../history/event-guidance-2026-11-15.md#7-검증-상태와-다음-기기-확인)에 남긴다.
