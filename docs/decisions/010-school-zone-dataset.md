# 010. 어린이보호구역 좌표 배포 — 저장소에 둔 정적 파일 + 해시 manifest

- 날짜: 2026-11-12
- 상태: **채택** (서버). 앱 쪽 항목(아래 '앱이 할 일')은 Android 담당과 확인할 제안이다
- 기준: Notion 「🚦 기획 v6」 1-3 이벤트 ① · ② 주정차·목적지, ERD 메모 「보호구역 목록은 서버 DB 없이 CDN 파일로 받는다 (해시 검증)」(2026-11-11)
- 관련: [007](007-remove-favorite-place.md) · [008](008-server-api-v1.md) · [009](009-core-features-v6-alignment.md)

## 배경

카드 H(보호구역 진입)와 B(목적지가 보호구역 300m 안)는 차가 **보호구역 위치를 알아야** 울린다.
기획은 공공데이터포털 「전국어린이보호구역표준데이터」 사본을 차량 DB(`local_school_zone`)에 두고
FusedLocation 근접 알림(반경 370m)으로 진입을 잡는다고 정했다. 서버가 이 사본을 내보내는 방법이 없었다.

| 사실 | 값 | 영향 |

(기획 v6 6장 11/18 기술 검증 항목). 어느 쪽이든 12,152곳을 한꺼번에 등록할 수는 없다 → 앱이 가까운 곳만 골라 등록한다.

## 결정

### 1. 서버 DB 에 넣지 않는다 — 저장소에 둔 정적 파일

- 생성 스크립트 `server/geo/build-school-zones.mjs` 가 원본을 받아 `server/src/main/resources/geo/school-zones.json` 을 만든다.
  이 파일을 **커밋**한다
- 반기마다 사람이 스크립트를 돌리고 PR 로 올린다. PR diff 에 건수 변화가 보이고, 배포는 기존 이미지 배포 그대로다
- 서버 DB 에 넣지 않는 이유: 서버는 이 데이터로 아무 판단도 하지 않는다(개인정보 경계 — 위치 대조는 차 안). 넣으면 테이블 ·
  적재 작업 · 갱신 이력 관리가 생기는데, 얻는 것은 없다

### 2. 파일 형식 (schema 1)

```json
{
  "schema": 1,
  "dataset": "school-zones",
  "source": "공공데이터포털 전국어린이보호구역표준데이터 (data.go.kr/data/15012891)",
  "referenceDate": "2026-10-27",
  "count": 12152,
  "zones": [[37.65083, 127.07781], ...]
}
```

- `zones` = `[위도, 경도]` 배열. 소수 5자리(약 1m) — 반경 370m 판정에 충분하고 파일이 작다
- 시설 이름·주소·종류는 넣지 않는다. 앱은 '보호구역 근처인가'만 본다 (`local_school_zone` = ID · 위도 · 경도, ERD)
- 원본에 안정된 ID 가 없다 → 파일에도 ID 를 두지 않는다. 앱은 갱신 때 **표 전체를 바꾼다**
- 정렬(위도 → 경도)해서 같은 원본이면 같은 바이트 → 같은 해시
- `referenceDate` = 원본 `데이터기준일자` 중 가장 늦은 날짜. 사람이 보는 표지이고, 바뀜 판단은 해시로 한다

생성 스크립트의 검사:

- 좌표가 숫자가 아니거나 국내 범위(위도 33~38.7, 경도 124.5~132) 밖인 행은 빼고 목록을 출력한다. 그런 행이 **1% 를 넘으면 멈춘다** (칸 뒤바뀜 같은 원본 문제)
- 결과가 비어 있으면 멈춘다
- **이전 파일보다 10% 넘게 줄면 멈춘다** (원본을 반만 받은 경우 — `--allow-shrink` 로만 통과)

### 3. API — manifest 와 내용 주소 파일

| | 경로 | 캐시 |
|---|---|---|
| manifest | `GET /api/v1/geo/school-zones` | `no-cache` + `ETag` = **manifest 자체의 해시** (304 지원) |
| 파일 | `GET /api/v1/geo/school-zones/{sha256}.json` | `max-age=1년, immutable`, **ETag 없음** |

```json
{ "dataset": "school-zones", "schema": 1, "referenceDate": "2026-10-27", "count": 12152,
  "sha256": "<파일 바이트의 SHA-256, 16진수 64자>", "bytes": 313438,
  "url": "/api/v1/geo/school-zones/<sha256>.json" }
```

- 서버는 **부팅 때** 파일을 읽어 형식 · 건수 · 범위를 검사하고 해시를 계산한다. 파일이 잘못되면 서버가 뜨지 않는다 — 잘못된 좌표를 내보내는 것보다 배포 실패가 낫다
- manifest ETag 를 파일 해시로 두지 않는다 — 파일이 그대로여도 `url`(CDN 이전)이나 항목이 바뀌면 앱이 새 manifest 를 받아야 한다
- 파일에는 ETag 를 두지 않는다. 경로가 이미 내용 주소라 필요 없고, **Tomcat 은 강한 ETag 가 붙은 응답을 압축하지 않는다** (`CompressionConfig.useCompression`, 코드 리뷰에서 확인)
- 파일 경로에 해시를 넣었다. 다른 해시로 부르면 404 → 오래된 manifest 를 든 앱이 새 파일을 옛 해시로 검증하는 일이 없다
- `url` 은 상대 경로일 수도, 절대 URL 일 수도 있다. 앱은 manifest 주소 기준으로 풀어서 쓴다 (RFC 3986). 나중에 CDN 으로 옮기면 `url` 만 바뀐다
- 응답 압축(gzip)을 켠다 — JSON 약 31만 바이트가 전송 때 약 8만 바이트로 준다. 해시는 압축 전 바이트 기준
- 인증 없음 (공공데이터). 동기화와 같은 앱용 API

### 4. CDN 은 지금 두지 않는다

- ERD 메모는 'CDN 파일'이었다. 시연·초기 규모(차 수십 대 × 반기 1회 × 약 80KB)는 EC2 하나로 충분하고, CDN 을 두면 버킷 · 배포 권한 · 무효화가 생긴다
- 계약을 manifest 의 `url` 로 두었으니, 차가 많아지면 서버를 고치지 않고도 옮길 수 있다 (앱 수정 없음)
- 옮길 때: 파일을 S3 에 해시 이름으로 올리고 manifest `url` 을 절대 URL 로

### 5. 같은 방식을 쓸 다음 데이터

고속도로 노선 좌표(카드 A) · 횡단보도 좌표(카드 I) · 운영 구간(카드 G, P1)도 '공공 좌표 → 차 사본' 이라 같은 모양을 쓴다:
`/api/v1/geo/{dataset}` manifest + `/{sha256}.json`. 이번에는 보호구역만 만든다.

## 앱이 할 일 (제안 — Android 담당 확인)

1. 카드 동기화 때(하루 1회 + 시동) manifest 를 부른다. `ETag` 를 저장해 `If-None-Match` 로 보내면 바뀌지 않은 날은 304
2. `sha256` 이 저장한 값과 다르면 파일을 받아 **SHA-256 을 직접 계산해 비교**한다. 다르면 버리고 옛 사본을 계속 쓴다
3. 맞으면 `local_school_zone` 을 **한 트랜잭션에서 통째로 교체**한다 (지우고 넣기). 원본에 ID 가 없어 행 단위 갱신은 못 한다
4. 근접 알림은 현재 위치에서 가까운 N곳만 등록하고, 등록한 지점에서 일정 거리 이상 움직이면 다시 고른다
   (Android 한도 100. Pleos 한도는 11/18 검증 후 N 을 정한다)
5. 첫 설치에서 파일을 아직 못 받았으면 이벤트 ① · ②-목적지는 조용히 쉰다 (틀린 안내보다 안내 없음)

## 고르지 않은 것

| 안 | 버린 이유 |
|---|---|
| 서버 DB 테이블 + 적재 작업 | 서버가 쓰지 않는 데이터. 위 1 |
| 지역별 타일 파일 (시도 · 격자) | 전국 파일이 압축 후 약 80KB 라 나눌 이득이 없다. 앱 저장 · 조회도 전국 1벌이 단순하다 |
| 차분(diff) 배포 | 원본에 안정된 ID 가 없어 차분을 정확히 만들 수 없다. 반기 1회 전체 교체로 충분 |
| 50m 안의 점까지 합치기 | 반경 370m 판정이 최대 50m 어긋난다. 근접 알림 슬롯은 '가까운 N곳' 방식으로 이미 해결된다 |
| 서버가 원본을 주기적으로 직접 수집 | 반기 갱신이라 자동화 이득이 작고, 사람이 PR 로 보는 편이 이상한 원본(반만 받기 · 좌표 뒤바뀜)을 잡는다. 공식 OpenAPI 키를 받으면 스크립트 입력만 바꾼다 |
| 카드 동기화 응답에 manifest 를 끼우기 | 앱 쪽 동기화 계약(이미 문서화됨)을 건드린다. 따로 두면 서로 영향이 없다 |
