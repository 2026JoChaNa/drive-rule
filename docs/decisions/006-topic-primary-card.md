# 006. Gleo 주제는 대표 카드에만 붙인다 — `topic` UQ 유지

- 날짜: 2026-11-11
- 상태: 결정 (MVP 범위) — 기획 회신 반영, ERD 변경 없음
- 요청: `docs/requests/2026-11-11-erd-screen-check-v5-2.md` 6번
- 관련: `rule_card.topic`(UQ) · `cached_card.topic` · [004](004-card-lifecycle.md)

## 배경

- 기획 요청: `rule_card.topic` UQ 를 풀고 `is_primary` 를 더한다. 한 주제에 카드 N장, Gleo 는 대표 카드 1장으로 답한다
- 004 는 "한 주제에 답이 둘이 되지 않게" `topic` 을 UQ 로 정했다

## 기획 회신 (2026-11-11)

- 한 주제의 카드 여러 장을 묶어 보여 주는 화면은 v5.2 어디에도 없다 (홈은 시행일 기준 목록, 07·08 은 카드 1장 안에서 분기만 바꿈)
- Gleo `ask_rule` 은 "topic 별 대표 카드 1장"으로 답한다 (기획 v4 Gleo 표)
- 대표 카드가 회수되면 **보류 문장**으로 답한다. 다른 카드를 자동으로 대표로 올리지 않는다

## 결정

- `topic` 은 **Gleo 대표 카드에만** 붙인다. 같은 주제의 다른 카드는 `topic` 을 비운다
- `topic` UQ 를 유지한다. `is_primary`·묶음 키는 두지 않는다 — '대표 카드' = `topic` 이 있는 카드
- 대표 카드를 회수(`RETIRED`)하면 서버가 그 카드의 `topic` 을 비운다 → 다른 카드에 붙일 수 있게
- 그 주제에 대표 카드가 없으면 Gleo 는 고정 응답 "확인된 안내가 없습니다. 주차한 뒤 화면에서 확인할 수 있습니다."로 답한다 (07-1 답변 보류 화면 그대로)
- 새 대표 지정은 운영이 한다 — 검수 대기열에서 다시 정한다

## 이유

- 묶음 화면이 없으니 `topic` 의 쓰임은 Gleo 키 하나다. 칸 하나에 뜻 하나
- `is_primary` 로 가면 "대표 1장"을 DB 가 막으려고 생성 컬럼 + UNIQUE 같은 장치가 더 필요하다. 지금 UQ 로 이미 막힌다
- 자동 대체를 하지 않는 것은 "답은 검수된 문장으로만" 원칙 때문이다 — 자동 대체는 검수하지 않은 대표 지정이 된다

## 영향

- ERD 변경 없음. 004 '규칙'의 `topic` UQ 문장 그대로
- 앱: 회수된 카드는 이미 `is_retired = 1` 로 Gleo 응답에서 빠진다 (004) — 추가 작업 없음
- 서버 CMS: 회수 시 `topic` 비우기, 대표 지정 화면

## 다시 검토할 때

- 한 주제의 카드 여러 장을 함께 보여 주는 화면이 생길 때 → 묶음 키 추가
- 대표 재지정을 대기열로 추적해야 할 때 → `review_request.request_type` 에 유형 추가 검토
