## 배경

- ERD 서버 구역 5개 테이블을 Flyway(`V1__init_server_schema.sql`)와 JPA 로 처음 구현한다
- Figma 화면 대부분(프로필 · 확인 이력 · 알림 · 이어 볼 질문 · 되묻기)은 **차량 DB 와 앱 로직**으로 동작한다. 서버가 화면에 주는 것은 카드 사본과 두 가지 접수 경로뿐이다

## 화면 → 서버 API

| 화면 | 서버가 하는 일 | API |
|---|---|---|
| 2·3·5·8 카드 · 근거 시트 | 게시 카드 사본 전달 (법령명·공포 번호·공포일 포함) | `GET /api/v1/cards/sync` |
| 3 근거 시트 '오류 신고' | 오류 신고 접수 (카드ID·버전) | `POST /api/v1/cards/{id}/error-reports` |
| 6 '새 질문' (주차 중 자유 질문) | 질문 → 게시 카드 1장 매칭, 실패 시 검수 대기열 | `POST /api/v1/questions` |
| 4·12 Gleo 주행 중 답변 | 없음 — 앱 사본의 대표 카드(`topic`)로 답한다 | — |
| 13 → 6 → 7 이어서 보기 | 없음 — `pending_question.topic` 으로 앱 사본에서 찾는다 | — |
| 1 처음 설정, 10·11 알림 | 없음 — 차량 DB | — |

검수 CMS(`/api/v1/admin/**`, 헤더 `X-Admin-Key`): 법령 개정 등록·분류, 검수자, 카드 작성·수정·검수 요청·교차 검수·회수·대표 주제 지정, 검수 요청 대기열.

## 결정

**1. 앱 API 는 인증하지 않는다, CMS 는 키 하나로 막는다**

- 앱은 식별자 없이 보낸다(003·005) — 인증할 주체가 없다
- CMS 사용자는 팀원 몇 명이라 계정 체계 대신 `ADMIN_API_KEY` 하나. 비어 있으면 CMS API 전체가 401

**2. 동기화는 `since` 증분 + 5분 겹침**

- `since` 없이 → 게시 카드 전체 + 회수 ID 전체. 있으면 그 시각 이후 바뀐 것만
- 응답 `nextSince` = 서버 시각 − 5분. 직전에 시작해 늦게 커밋된 변경을 놓치지 않으려고 겹쳐 받는다. 앱은 카드 ID 로 덮어쓰면 된다 (멱등)

**3. 버전은 '검수 묶음' 번호 — 검수 기록이 있는 버전을 다시 검수에 올릴 때 +1**

- 004 는 "재검수 → PUBLISHED 시 version + 1" 이었다. `card_review` UQ(card_id, card_version, reviewer_id) 때문에 시점을 앞당겼다
  - 반려 → 수정 → 재요청 때 같은 버전이면, 반려한 검수자가 고친 내용을 다시 검수할 수 없다 (UQ 위반)
  - 그래서 **검수 요청(`submit`) 시점에 그 버전의 검수 기록이 있으면 +1** 한다. 처음 게시는 1, 게시 후 수정·재게시는 2 …
- 결과는 004 와 같다: 게시 카드를 고치면 다음 게시본의 버전이 1 오른다
- 게시 조건: 같은 버전에 서로 다른 검수자 **승인 2건**. 반려 1건이면 `DRAFT`
- 대표 주제(`topic`) 지정·해제는 문장이 바뀌지 않으므로 재검수 없이 한다 (006 '대표 지정 화면'). 동기화로 다시 나간다

**4. 자유 질문 매칭은 '카드 고르기'만 — 임시로 글자 2-gram**

- 서버는 답 문장을 만들지 않고 게시 카드 ID·버전만 돌려준다. 되묻기·답변은 앱이 자기 사본의 `decision_json` 으로 한다 (002)
- 매칭 실패만 `review_request(QUESTION)` 로 쌓는다 — 003 의 '매칭 실패 비율' 근사치
- 지금 매칭기는 질문과 카드 문장(제목·주제·두 장면)이 공유하는 글자 2-gram 수로 고르고, 애매하면(2개 미만·동점) 매칭하지 않는다. `QuestionMatcher` 구현만 바꾸면 교체된다

**5. 오류 응답 형식** — RFC 9457 ProblemDetail + `code`(고정 문자열) + `errors`(검증 실패 목록)

## 열린 질문

1. (개발·기획) **자유 질문 매칭 방식** — 2-gram 은 카드 문장에 없는 표현("술 마신 동료한테")에 약하다. 후보: 카드별 예시 질문·동의어 칸 추가(ERD 변경), 분류 모델(답은 만들지 않고 카드만 고름). 카드 27장 기준으로 정한다
2. (개발) **오류 신고·질문 남용** — 식별자가 없어 기기별 제한을 못 건다 (005). 서버 IP 단위 요청 수 제한부터 검토
3. (개발) 법령 원문 Open API(`LAW_API_OC`) 연동은 이번 범위 밖 — 지금은 CMS 가 법령 개정을 손으로 등록한다

## Figma(섹션 `현대차`)와 결정이 다른 곳 — 기획 확인 필요

기획서·Figma 는 고치지 않고 차이만 남긴다.

| 화면 | Figma | 결정 | 서버 영향 |

| 1 처음 설정 | '면허를 딴 연월'을 묻는다 (1 / 2), 다음 화면은 '주로 운전하는 상황' | 001: 프로필은 **이름만**. v5.2 에 반영 완료라고 회신받음 | 없음 (차량 DB). 이 섹션이 v5.2 이전 판인지 확인 필요 |

## 다시 검토할 때

- CMS 사용자가 팀 밖으로 늘 때 → 계정·권한 (Spring Security)
- 카드가 수십 장 이상이고 동기화 응답이 커질 때 → 페이지 나누기 또는 CDN 파일(manifest, 보호구역 목록과 같은 방식)
