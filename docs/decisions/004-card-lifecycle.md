# 004. 카드 수명주기 — 수정은 게시 해제 후 재검수, 회수는 차량까지 전파

- 날짜: 2026-11-11
- 상태: 결정 (MVP 범위)
- 관련: `rule_card.status` · `rule_card.version` · `rule_card.topic`(UQ) · `cached_card.is_retired` · `card_review.card_version`

## 배경

- `rule_card` 는 카드 1장 = 1행이다. 게시본과 수정 중인 작업본을 따로 두지 않는다
- 그래서 게시 카드를 고치면 같은 행이 덮어써지고, 검수 전 내용이 차량으로 나갈 위험이 있다
- 잘못 게시한 카드를 차량에서 내릴 신호가 없었다 — 차에 남은 사본이 틀린 법규 안내를 계속 낸다

## 결정

**상태 4개** (`rule_card.status`)

| 상태 | 뜻 | 동기화 |
|---|---|---|
| `DRAFT` | 작성·수정 중 | 보내지 않음 |
| `IN_REVIEW` | 2인 교차 검수 중 | 보내지 않음 |
| `PUBLISHED` | 게시 | 내용 + `version` 전송 |
| `RETIRED` | 회수 | 카드 ID 만 전송 → 앱이 `is_retired = 1` |

**규칙**

- 게시 카드를 고치면 `DRAFT` 로 돌아간다 → 재검수 → `PUBLISHED` 시 `version + 1`
- 수정·재검수 중에도 **앱은 마지막으로 받은 사본을 그대로 쓴다** (서버가 회수 신호를 보내기 전까지)
- 내용이 틀려 즉시 내려야 하면 수정이 아니라 **회수(`RETIRED`)** 한다
- 앱은 회수된 카드를 알림·목록·Gleo 응답에서 빼고, 행은 지우지 않는다 (확인 이력이 참조)
- Gleo `topic` 은 카드 1장에만 붙는다 (`UQ`) — 한 주제에 답이 둘이 되지 않게

## 이유

- 버전별 내용 테이블(`rule_card_version`)은 정확하지만 MVP(카드 7~27장)에 과하다
- 게시 해제 → 재검수 규칙만으로 "검수 안 된 문장이 차에 나가는 일"은 막힌다
- 법규 안내 앱에서 틀린 카드가 차에 남는 것은 가장 위험한 실패라, 회수 신호는 MVP 에도 필요하다

## 한계 (알고 받아들이는 것)

- **검수한 버전의 내용이 서버에 남지 않는다** — `card_review` 는 "몇 번째 버전을 누가 승인했나"만 기록
- 수정 중에 처음 설치한 차량은 그 카드를 받지 못한다 (재게시까지 짧은 공백)

## 다시 검토할 때

- 검수 증빙(어떤 문장을 승인했나)을 외부에 보여야 할 때 → `card_review` 에 내용 스냅샷 `JSON` 추가
- 카드가 많아져 수정 공백이 문제가 될 때 → `rule_card_version` 으로 게시본·작업본 분리
